# 부트스트랩 단계

이 절차의 최종 대상은 Beta 1 `2026100804`입니다. 중간 버전은 이전 도구가 다음 버전의 소스를 처리할 수 있도록 컴파일 기능을 확보하는 데 사용합니다.

| 단계 | 소스 | 빌드 입력 도구 | 목적 |
| --- | --- | --- | --- |
| `seed-gen1` | `1584ede` | Swift 씨앗·Clang | 독립적인 최초 네 도구 생성 |
| `backend-upgrade` | `e7467cf` | 최초 네 도구 | 전역 초기값과 함수 주소 HMIR 지원 |
| `field-bridge` | `e7467cf` | 최초 도구 + 새 백엔드 | 명시적 필드 표지 등 문법 지원 |
| `alias-upgrade` | `3e4dbb0` + 숫자 기본값 패치 | 직전 네 도구 | 숫자 기본값 표기와 조건 문법 지원 |
| `payload-bridge` | `6cc6773` | 직전 네 도구 | 종류 payload 분기 문법 지원 |
| `container-bridge` | `add6b94` | 직전 네 도구 | 선택값 등 컨테이너 타입 이름 처리 |
| `none-upgrade` | `add6b94` + `578ee7ae` 수정 | 직전 네 도구 | 없음 비교에 반대쪽 선택값의 타입 문맥 적용 |
| `beta1-gen1` | `d2ce1c9` | 직전 네 도구 | 현재 Beta 1 네 도구 생성 |
| `beta1-gen2` | `d2ce1c9` | Beta 1 1세대 | 현재 소스의 자체 빌드 |
| `beta1-gen3` | `d2ce1c9` | Beta 1 2세대 | 고정점 비교용 자체 빌드 |

전체 커밋 번호는 `reference/versions.json`에 기록합니다. `d2ce1c9` 패키지의 컴파일러·라이브러리·네이티브 대상 소스는 `032483b`의 소스와 같습니다. 두 커밋의 차이는 패키지 SDK 고정값 등 배포 설정입니다.

`backend-upgrade`는 백엔드만, `none-upgrade`는 프런트엔드만 교체합니다. 나머지 도구는 직전 세대 파일을 그대로 복사합니다. 매번 직전 세대의 네 실행 파일을 명시적으로 지정하며, 비교 대상 배포 파일을 빌드 도구로 사용하지 않습니다.

## 숫자 기본값 패치

`alias-bridge` 아카이브는 `3e4dbb0` 원본 소스입니다. 압축을 푼 뒤 `scripts/backport-numeric-defaults.swift`로 `파싱기본값숫자타입인가`의 판별식 세 줄만 수정합니다. 변경은 `70597c04`에서 도입된 기본값 인식과 같으며 다음 이름을 추가합니다.

- 자연수 계열: `자연수`, `큰자연수`
- 정수 계열: `정수`, `큰정수`
- 실수 계열: `실수`

새 표기를 쓰는 라이브러리가 기존 컴파일러의 기본값 파서에서 거절되는 부트스트랩 단절을 해결하기 위한 변경입니다. 패치의 원문이 예상과 다르면 실행을 중단합니다. 패치 후 소스 파일 목록·해시를 기록하고 마지막에 다시 검사합니다. 현재 Beta 1 소스에는 패치를 적용하지 않습니다.

## 실패 처리

각 빌드의 종료 코드가 0이고 필요한 산출물이 실제로 있어야 다음 단계로 이동합니다. 기존 출력 폴더를 재사용하지 않습니다. 실패한 단계와 로그를 보고서에 기록하고 종료 코드 1을 반환합니다. 최종 두 세대의 바이트가 같더라도 배포용 서명 전 빌드 및 서명을 정규화한 배포 사본과 다르면 `verified`로 판정하지 않습니다.

## 없음 비교 패치

`none-bridge`에 적용하는 `578ee7ae` 수정은 배열 원소 타입 추론과 선택값의 `없음` 비교를 처리합니다. 패치는 `reference/bootstrap-none.patch`에 원문으로 포함되어 있으며, 다섯 파일을 변경합니다. 최종 Beta 1 소스는 원본 아카이브 그대로 사용합니다.

## 소스 위치 경로

Beta 1 배포 파일에는 컴파일 당시의 소스 파일 절대 경로가 런타임 오류 메시지로 포함되어 있습니다. 재현 검증은 비교 파일의 고정 해시를 먼저 확인한 뒤 `release-source-prefix.swift`로 네 파일의 소스 접두 경로를 읽습니다. 네 파일에서 발견한 소스 접두 경로가 하나로 일치해야 진행합니다. 최적화로 경로 기록이 없는 파일도 읽지만, 발견한 경로가 없거나 서로 다르면 중단합니다. 비교 파일은 이 과정에서도 실행하지 않습니다.

검증 드라이버는 읽은 값을 `HMJE_RELEASE_SOURCE_PREFIX`로 최종 빌드에 전달합니다. 검증 호스트에 배포 당시의 폴더를 만들 필요는 없으며 사용자 계정·체크아웃 위치와 무관하게 실행할 수 있습니다.

`rebuild-beta1.sh`를 단독으로 실행하면 현재 압축 해제한 소스 경로를 사용합니다. 다른 빌드의 소스 위치를 맞출 때에는 `HMJE_RELEASE_SOURCE_PREFIX`에 비교 기준의 절대 경로를 지정할 수 있습니다. 고정된 Beta 1 배포 파일과 비교하는 전체 절차에서는 검증 드라이버가 해시를 확인한 파일에서 값을 읽으므로 호출자의 환경 변수로 비교 기준을 바꾸지 않습니다.

접두 경로가 다르면 `backend-prefix.sh`가 새로 생성한 HMIR에 `map-source-prefix.swift`를 적용합니다. 변환 대상은 `원본위치` 기록과 `선택값검사` 오류 문자열의 첫 파일 경로뿐이며 다른 명령에서 해당 경로가 발견되면 실패합니다. 접두 경로가 같으면 변환 없이 백엔드로 전달합니다. 변환할 때에는 원래 HMIR의 `.unmapped` 사본을 생성합니다. 제품조정기는 성공한 호출의 중간 IR 폴더를 삭제하며 최종 실행 파일·프로젝트 계획·빌드 로그가 남습니다.

이 변환은 바이너리 비교 이후의 정규화가 아닙니다. 생성된 바이너리는 경로를 제거하거나 다시 쓰지 않고 서명 전 배포 빌드 파일의 원본 해시와 비교합니다. 현재 검증 코드 해시는 `reference/seed-beta1.sha256`, 이전 전체 실행 당시의 입력 식별값은 `evidence/original-inputs.sha256`과 `evidence/original-seed-beta1.sha256`에 구분하여 보존합니다.

## 최종 네이티브 빌드

초기 단계는 단일 LLVM 모듈로 빌드합니다. Beta 1의 세 단계는 `HMJE_OBJECT_CACHE=on`으로 배포본의 분할 컴파일·ThinLTO 경로를 선택합니다. `--캐시끄기`와 새 출력 폴더를 함께 사용하므로 이전 바이너리나 오브젝트를 재사용하지 않습니다. 분할 단위 생성 및 링크 기록은 각 도구의 로그에서 확인할 수 있습니다.
